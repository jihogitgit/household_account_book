**날짜:** 2026-05-22

**방향:** 기존 변동지출 단순화(생활 통합) 유지, 버그 픽스에 집중

## 1. 배경 및 문제 정의

### 현재 카테고리 구조

`utils.py`의 `rules` 리스트가 앱의 실제 분류 근거이며, 4-튜플 `(대분류, 소분류, IsFixed, lambda)` 형식으로 정의된다.

| 대분류 | 소분류 | 비고 |
|-------|-------|-----|
| 수입 | 급여, 이자/캐시백 | 급여는 통장명 "급여통장" + 적요 조건 |
| 고정지출 | 월세/이자, 보험, 연금, 청약, 적금/저축, 교통/통신, 공과금, 용돈 | IsFixed=True |
| 변동지출 | 생활, 배달, 병원 | 배달/병원 특정 적요 매칭, 나머지는 "생활"로 통합 (의도적 설계) |
| 경조사 | 경조사 | `_통장 == "경조사"`이면 전량 자동 분류 |
| 내부이체 | 생활비 이체, 여행비 이체, 계좌간 이체, 모임 출금 | 집계 제외 |
| 기타 | 개인 이체 | 입금/출금 미분류 폴백 |
| 미분류 | 미분류 | 위 룰 미매칭 폴백 |

### 경조사 통장 동작 방식

경조사 통장은 별도 xlsx 파일로 업로드되며, `_통장` 컬럼이 `"경조사"`로 설정된다.  
모든 거래가 `("경조사", "경조사", ...)` 룰로 자동 분류되므로 미분류로 빠지지 않는다.  
"효도" 소분류는 사용자가 수동 재지정 시 선택할 수 있는 옵션으로 필요하다.

### 이슈 1 — `categorize.py` 미사용 + 보안 위험

- **조치:** 파일 삭제

### 이슈 2 — `tabs/uncategorized.py` CAT_MAP 불일치

현재 CAT_MAP:
```python
"변동지출": ["생활", "배달", "병원", "경조사", "효도"],  # ← "경조사", "효도"는 여기 있으면 안 됨
"경조사":  ["경조사"],                                  # ← "효도" 누락
```

- "경조사"와 "효도"는 변동지출 소분류가 아님 → 사용자가 변동지출로 잘못 저장할 위험
- "효도"는 경조사 대분류의 소분류여야 함 (경조사 통장 내 항목 수동 재분류 시 필요)

## 4. 변경하지 않는 항목 (의도적 제외)

| 항목 | 이유 |
|-----|-----|
| 변동지출 "생활" 통합 | 사용자 의도적 설계 — 세분화보다 단순성 우선 |
